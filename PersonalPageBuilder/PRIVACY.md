# 隐私与数据安全声明

本声明适用于 Personal Page Builder（以下简称「本程序」）的全部源码与发布包。
当前对应版本：程序目录下的 `personal_page_builder.py` 与 `ppb_preview.py`。

---

## 一、一句话概括

本程序**完全在你的电脑上本地运行**，不注册账号、不联网收集任何信息、不向任何服务器上传数据。
唯一的对外网络行为是：当你**主动点击**「同步到页面」时，由你本机的 git 把改动推送到**你自己的** GitHub 仓库。

首次启动时，程序会先显示本声明（摘要 + 完整原文），你必须点【同意并继续】才会进入设置与主界面；
点【不同意，退出】或关闭窗口，程序立即退出，不会读写任何素材或仓库文件。
确认状态只记录版本号与时间（`privacy.json`），不含设备标识；想重新征询，删掉该文件即可。

---

## 二、程序会读取哪些内容

1. 你指定的**素材目录**：只读该目录**第一层**的图片与视频文件（不递归子目录），用于生成缩略图、压缩、复制。
   文件名以 `.` 开头的隐藏文件一律跳过。
2. 你指定的**仓库目录**：只读你指定的那个页面文件（默认 `index.html`），用于定位作品区并替换内容。
3. 你自己的**数据目录**（见第三节）：读取配置、编辑存档、压缩偏好。
4. 系统里已安装的 **git**（提交与推送）和 **ffmpeg**（仅用于给视频抽首帧图片）。
   两者都是本机进程，不联网，除非你自己让 git 联网推送。

程序**不会**读取：浏览器数据（书签、Cookie、历史、密码）、聊天记录、剪贴板、桌面或文档目录、
其他磁盘上的文件、系统账户信息。它没有全盘扫描逻辑，扫描范围只有你亲手填的那两个目录。

---

## 三、程序会写入哪些内容（完整清单）

写入位置只有三处：**数据目录**、**素材目录之外的仓库内文件**、**系统临时目录（写入后立即改名，不残留）**。

### 1. 数据目录：`~/.personal_page_builder/`
Windows 上是 `C:\Users\<你的用户名>\.personal_page_builder\`。
可用环境变量 `PPB_DATA_DIR` 整体改到别处（例如 U 盘）。

| 文件 | 内容 | 何时写入 |
|---|---|---|
| `privacy.json` | 只记录「已确认的声明版本号」和确认时间，不含任何设备信息 | 仅在首次启动点【同意并继续】时；拒绝则不写 |
| `config.json` | 你填的素材目录、仓库目录、页面文件名、远端名、分支、ffmpeg 路径（含本机绝对路径） | 只在设置面板点「保存」且内容**有变化**时 |
| `settings.json` | 图片压缩开关、格式、长边上限、质量 | 只在压缩面板点「保存」且内容**有变化**时 |
| `repos/<仓库指纹>/state.json` | 栏目标题、版式、卡片标题与描述、素材原文件路径 | 编辑后停止操作 0.6 秒合并写一次，且内容**有变化**时 |
| `repos/<仓库指纹>/backup/index.before-text-edit.html` | 在预览里直接改页面文字前的原文件备份 | 本次会话第一次改页面文字时，仅一次 |
| `repos/<仓库指纹>/backup/<页面名>.bak` | 自动插入 PORTFOLIO 标记前的原文件备份 | 仅在你同意自动插入标记时，仅一次 |
| `cache/frames/` | 视频首帧缩略图（jpg） | 首次显示视频卡片时 |
| `cache/optimized/` | 压缩后的图片，按「源路径 + 修改时间 + 体积 + 参数」命名 | 同步时按需生成，可随时删 |
| `cache/preview/index.html` | 预览用的临时页面 | 每次编辑后 |

`state.json` 损坏（读到非法内容）时，程序会把它改名为 `state.json.corrupt-<时间戳>.json` 保留，
而不是直接覆盖掉，同时在日志里提示。

### 2. 你的仓库目录内
1. 你指定的**页面文件**：只替换 `<!-- PORTFOLIO_START -->` 与 `<!-- PORTFOLIO_END -->` 之间的内容；
   在预览里改页面标题、段落等文字时，会直接改写对应文字（仅限该文字在整页里唯一出现的场合）。
2. `assets/images/`、`assets/videos/`：同步时复制（图片按压缩设置重新编码）进去的素材副本。
3. 插入标记时**不会**在仓库里留下 `.bak`，备份统一放在数据目录。

### 3. 程序绝不写入的地方
1. Windows 注册表、系统目录（`C:\Windows`、`Program Files`）、环境变量
2. 开机启动项、计划任务、系统服务
3. 你的桌面、文档、下载等目录
4. 其他用户的主目录
5. `hosts` 文件、Hosts 之外的任何系统配置
6. 浏览器配置、任何第三方软件的数据目录

安装与卸载都是「复制 / 删除一个文件夹」，不写注册表、不留后台常驻进程。

## 四、不收集的信息

1. **无遥测**：不上报启动次数、使用时长、功能点击、崩溃堆栈。
2. **无账号体系**：不需要登录，程序里没有账号、密码、令牌字段。
3. **无设备标识**：不生成 UUID、不读取网卡 MAC、不读取硬件序列号。
4. **无广告与统计 SDK**：依赖只有 Pillow、pywebview、watchdog 三个通用库，均不联网上报。
5. **不自动检查更新**：不存在「启动时请求服务器」的逻辑。

## 五、网络行为与端口防护

### 1. 实时预览（本机回环）
预览窗口是一个只绑定 `127.0.0.1` 的小型 HTTP 服务，端口由系统**随机分配**，服务随窗口关闭而停止。
主程序通过同一个回环端口读取你在预览里的编辑动作，除此之外没有任何网络请求。

为防其他网站借道本机端口读取你的文件，服务端做了四层限制：

1. **Host 白名单**：只接受 `Host` 为 `127.0.0.1` / `localhost` / `::1` 的请求。
   即使恶意网页把自己的域名解析到 127.0.0.1（DNS rebinding），Host 也会是那个域名，直接被 403 拦下。
2. **Origin 校验**：带 `Origin` 且不是本机地址的请求一律 403；服务也不返回任何 CORS 放行头，
   因此浏览器端的跨站读取在预检阶段就会失败。
3. **敏感路径拒绝**：`.git`、`.ssh`、`.gnupg`、`.env*`、`.netrc`、`.npmrc`、`.htpasswd`、
   `id_rsa`、`id_ed25519` 等路径无论出现在哪一层，一律 403。
   即便仓库的 `.git/config` 里存着带令牌的远端地址，也不会被读走。
4. **路径越界拒绝**：所有请求解析后必须落在素材目录或仓库目录内，`..`、URL 编码的 `%2e%2e`
   都会被 403；文件不存在返回 404。

### 2. git 推送
只有点击「同步到页面」并确认后才会执行 `git add / commit / push`。
认证由你本机的 git 负责（凭据管理器、SSH key 或 Personal Access Token），
**本程序不读取、不保存、不转发任何密码或令牌**。

### 3. 绝对不做的网络行为
不上传配置、存档、路径、素材、页面内容到任何第三方服务器；不发起任何后台请求；
不下载任何远程资源到你的仓库。

## 六、数据完整性：不会重复写、不会写坏

针对「配置文件被反复写、写一半断电导致损坏」两类风险，程序做了以下约束：

1. **内容相同就不写**：所有 JSON 保存（`config.json`、`settings.json`、`state.json`）
   都先与磁盘上的内容逐字比较，完全一致时**跳过写入**，文件修改时间也不变。
   重复触发保存、反复打开设置面板点保存，都不会产生多余写盘。
2. **原子替换**：写入先落到同目录的临时文件，`flush` + `fsync` 落盘后再用 `os.replace` 整体替换。
   中途断电或进程被杀，原文件仍是上一个完整版本，不会出现半截 JSON。
3. **失败自动清理**：写入出错时删除临时文件并把错误抛给界面，不会静默吞掉。
4. **异常退出残留清理**：启动时清理超过 1 分钟的 `*.tmp`，目录里不会越积越多。
5. **写入去抖**：编辑内容后停止操作 0.6 秒才合并成一次保存，连续打字不会产生几百次写盘。
6. **启动只读**：已有有效配置时，启动过程**不写** `config.json`；已有存档时**不写** `state.json`。
   只有「首次配置」「首次从页面导入卡片」这两种情况才会各写一次。
7. **损坏隔离**：读不出来的存档会被改名保留（见第三节），不会被新内容覆盖。

## 七、权限

1. **POSIX（macOS / Linux）**：数据目录权限收紧为 `700`，`config.json`、`settings.json` 为 `600`，
   同一台机器上的其他用户无法读取。
2. **Windows**：用户目录本身默认只有你本人和管理员可访问；程序**不**去改 ACL，
   避免把权限改坏导致你自己反而打不开。
3. 数据目录**不在程序目录内**，也不在你的 git 仓库内，因此不会被 `git push` 带出去，
   卸载或复制程序也不会带走或覆盖你的数据。

## 八、你可以做的

1. **完全删除**：退出程序，删掉 `~/.personal_page_builder/` 整个目录即可，不留残留。
   仓库里已同步的素材与页面属于你自己的项目，请另行处理。
2. **重新确认或撤回**：删掉 `~/.personal_page_builder/privacy.json`，下次启动会重新征询；
   在设置窗里也可以随时点【隐私声明】重新阅读（只读，不会改动已确认状态）。
2. **换位置**：设置环境变量 `PPB_DATA_DIR` 指向别处（如加密盘、U 盘）。
3. **不留路径痕迹**：数据目录里的 `config.json` 含本机绝对路径，属于本机隐私；
   它不会被上传。若你手动把它放进公开仓库，请自行删除。
4. **关掉预览**：顶栏「预览」按钮可随时关闭；关闭后不再监听任何端口。
5. **核查**：主窗口日志第一行会打印当前生效的 `config.json` 路径。
6. **备份存档**：复制整个数据目录即可，路径不用改。

## 九、已知边界（如实说明）

1. 本程序不是加密工具，数据以**明文**存放在你的用户目录；能登录你系统账户的人可以看到。
2. 预览服务运行期间，**本机上的其他程序**可以直接访问那个回环端口。
   但同机程序本来就有读取你文件的权限，这不是新增的越权面；跨站访问已被第五节的规则挡住。
3. GitHub 账号安全、git 凭据的安全，取决于你自己的 git 配置与操作系统凭据存储，本程序不介入。
4. 图片压缩由 Pillow 在你本机完成，不联网；但压缩后的图片会进入你的仓库，等同于公开，
   请勿把含隐私信息的图片放进素材目录。
5. 如果你把数据目录放进云同步盘（OneDrive、iCloud 等），同步行为由该云服务负责，不在本声明范围内。
6. 程序假设运行环境可信（你自己的电脑、自己的账户）。若在公用电脑上使用，
   请使用完删除数据目录，并注意 git 凭据可能残留在系统凭据管理器中。
